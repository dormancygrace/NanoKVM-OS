# HID profile install and USB reset/reopen

Admin POST /api/hid/mode and POST /api/hid/reset now use the Rust lifecycle coordinator. Validation, idempotent current-profile no-op, response codes, fixed script selection, source permissions, 10-second restart command and two-second/100ms HID reopen retry are covered. The complete virtual-device composition API and internal-token USB recover HTTP exception remain pending.

The resolver interprets firmware absolute symlinks inside the isolated virtual root. Installing a profile preserves Alpine /etc/init.d/S03usbdev -> /usr/libexec/nanokvm/legacy/S03usbdev and atomically replaces/fsyncs its target. Dangling links, escaping relative paths and link loops fail closed. A failed profile copy reopens current HID/LED descriptors instead of leaving input detached.

Both mutations reserve manual priority, preempt/drain a background/HID addon and pause browser tickets under the ownership transition. Cleanup invalidates every queued/manual generation, releases held reports/external ownership and then closes descriptors/readers before the action. Reset keeps the socket-specific ownership lease and allows fresh reports after device nodes return. Failed commands preserve neutral-retry recovery; successful gadget reset clears stale physical held state. All IO remains on bounded workers.

Profile installation returns its success response before a single deduplicated reboot dispatch delayed 500ms; reboot errors are logged, as Go ignores them after responding. Fixed native actions cannot execute host firmware scripts/reboot from an isolated root. Trusted test executors record actions and simulate file nodes; no native USB/reboot has run. Production activation and nonloopback listener guards remain. The runner owns a new process group, has timeout/stop polling and kills/reaps the shell and descendants on failure/cancellation. Shutdown signals it before waiting for input cleanup.
