# Internal USB recovery and HTTP execution admission

POST /api/internal/usb/recover now authenticates the existing /etc/kvm/.picoclaw_internal_token independently of browser JWT, roles and authentication-disable. Existing credentials/cache semantics are retained; a missing/empty token becomes 64 cryptographically random bytes encoded as padded URL-safe base64 and persisted atomically with mode 0600. Only the actual loopback peer (including Go-compatible IPv4-mapped loopback) can authenticate; forwarded IP and a browser login cannot substitute for it. Comparison uses maintained ctutils already in the lockfile. No credential is logged or returned.

The companion HTTP listener preserves Go's exact internal allowlist: USB recover and PicoClaw mcp/runtime-session/screenshot/actions/load-image. An authenticated loopback request reaches the same app; other requests receive the normal HTTPS 307 with path/query intact. Pending PicoClaw handlers still return 501 after this access gate. The USB recovery action uses the guarded/injected reset/reopen lifecycle; actual native firmware commands remain refused for isolated roots.

Blocking-job admission now happens after async body buffering. Incomplete requests no longer hold the four execution slots needed by other API or socket work. This keeps the Go streaming policy: no global request-body or response-write deadline is added. Header/idle transport policy and large endpoint-specific upload limits remain required in later integration.

Qualification: check-v3.py --host --target --tls passes 65 tests on both architectures (31 unit, 20 API, fourteen actual-socket tests), fmt/clippy, static riscv64 musl/QEMU and real verified TLS lifecycle. Tests cover persisted/generated/private token, actual peer/forwarding/IPv6-mapped semantics, browser-independent recovery, isolated command refusal, successful injected device recovery, four incomplete bodies with concurrent account API and actual plaintext HTTP bypass versus invalid-token/nonallowlisted 307. The target TLS fixture now records the internal HTTP exception explicitly. Existing thirteen Go oracle responses and two-way JWT checks remain included. No dependencies or stand changes.

Ledger: 28 isolated implementations, one partial WS, 175 pending. Full USB composition/budget/rollback, monitor/EDID association, HTTP paste and native/media/addon/package/hardware parity remain. H.265 WebRTC must always return h265-webrtc-disabled regardless of hardware/software crypto; direct H.265 is in scope.
