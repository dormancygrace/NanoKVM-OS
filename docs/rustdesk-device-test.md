# RustDesk: испытание NanoKVM на устройстве

Дата: 3 октября 2026. Стенд: 192.168.4.128. Alpine 3.24.2,
Linux 7.2.6-nanokvm-os-r1. Клиент Windows RustDesk 1.4.9+67.

Видеосеанс настоящего клиента подтверждён. NanoKVM отдаёт готовый поток
аппаратного энкодера через существующий Go-сервис; декодирование на SG2002
не добавлялось. Клиент показывает HDMI 1440×2560, H.265, 4:2:0.
На нескольких наблюдениях индикатор клиента показывал 26–40 FPS, обычно
35–40 FPS, при запрошенных 50 FPS. Это наблюдение на статичном рабочем столе,
а не нагрузочный тест или измерение задержки.

## Что проверено

- Производственная CGO-сборка сервера с текущим Go runtime NanoKVM и
  квалифицированным комплектом аппаратных библиотек успешно собрана.
  libkvm.so и libkvm_mmf.so совпадают по SHA-256 с установленными до теста.
- В тестовую ветку включены изменения основного интерфейса до 110d0d6.
  Карточка RustDesk смонтирована в Software → Add-ons и проверена в Chrome Main.
- nanokvm-app 2.0_beta8-r1 установлен обычной APK-транзакцией.
  nanokvm-rustdesk установлен отдельно, без автозапуска после установки.
- Настройки сохранены через карточку Add-ons. Пароль не выдаётся в статусе.
- Публичный ID-сервер rs-ny.rustdesk.com подтвердил регистрацию ID 1320947846.
- Установленный клиент подключился как 1320947846@public с принудительным relay.
  Параметры основного клиента desk.globalte.ru не изменялись.
  В журнале демона: secure true, authenticated, 1440x2560 H.265 @ 50 FPS;
  зашифрованный relay ovh-fr2.rustdesk.com:21117 и первая отправленная видеорамка.
  Реальное изображение и H265 подтверждены в окне клиента.
- Веб-видео работало после обновления и после переустановки.
- OpenRC stop/start сохранил конфигурацию и ID; stop очистил runtime status.
- Обновление APK 0.1.0-r0 → r1 восстановило ранее запущенную службу.
  Системный nkos-apply-updates дополнительно перезапустил её; проверка проводилась
  после завершения обработчика обновлений, ошибок в его итоговом статусе нет.
- Удаление остановило службу, удалило бинарник и запись автозапуска.
  Конфигурация, identity и settings-output сохранились с прежними SHA-256.
  Повторная установка оставила службу остановленной и сохранила тот же ID.
- Каталог конфигурации 0700, конфигурация и оба Unix-сокета 0600, владелец root.
- Полный Go test -tags teststub ./... после объединения веток прошёл;
  TypeScript/Vite production build с подключённой карточкой прошёл.

## Что ограничило проверку

1. Уже открытый браузерный контроллер удерживал ввод. Попытка события мыши
   через RustDesk получила HTTP 409 Conflict и закончила сеанс, как предусмотрено
   текущей политикой владения вводом. Физический результат клика не подтверждён.
   Для независимой проверки мыши нужно освободить браузерный контроллер.
2. В текущей USB-композиции привязан только hid.GS2, /dev/hidg2.
   Клавиатура и относительная мышь выключены. Композиция не менялась.
   Проверка клавиатуры, модификаторов, колеса и удержанных кнопок не завершена.
3. Публичный ID-сервер иногда не отвечал по TCP; клиент показал
   “Failed to connect to rs-ny.rustdesk.com:21116: Please try later”.
   Долговременная стабильность публичного relay не квалифицирована.
4. Первая попытка через локальный TCP и SSH-туннель не состоялась:
   sshd стенда запрещает port forwarding. Параметры sshd не менялись,
   loopback-порт 21118 не публиковался в LAN.
5. H.264, несколько зрителей, отдельный собственный ID-сервер и
   сохранение после перезагрузки не проверялись. Перезагрузка не проводилась.

## Состояние после теста

Тестовые пакеты nanokvm-app 2.0_beta8-r1 и nanokvm-rustdesk 0.1.0-r1
остаются установленными. Служба RustDesk остановлена. Настройки доступа,
пароль и ID сохранены на устройстве. H.265, портретное разрешение и
Absolute Pointer Windows-only сохранены. Конфигурация USB не менялась.

Тестовая ветка: codex/rustdesk-addon-20261003.
Основной checkout не изменялся. APK локальные, неподписанные; публикации
в репозитории пакетов не было.
