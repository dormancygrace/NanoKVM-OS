# Shared native video source

This stage connects one device-wide video source to Runtime, the native actor and HDMI read leases. It does not complete MJPEG/Direct/WebRTC HTTP or WS routes. The full migration goal remains active; the route ledger remains 64 implemented in isolation, one partial and 139 pending out of 204.

The source shares an immutable encoder configuration and one native capture session among matching subscribers. Passive subscriptions adopt the explicit selection, then a live session, then H.265. Explicit mismatch returns the retained codec conflict. Selection changes retire old decoder queues immediately; a replacement waits for the previous bounded native read to return and resolves passive selection again after draining. A closed last viewer does not cancel in-flight IPC or poison the native owner.

Admission is limited to 64 subscribers. Each decoder queue holds at most 24 shared frames, waits for an initial IDR, preserves native errors and drains stale frames on overflow before requesting another IDR. The capture owner coalesces feedback at 500ms. Failed native admission restores the request intent, including under the actor's saturated eight-slot queue. Closing a subscription clears its queued owners and takes priority over delivery; this deliberately fixes retained Go queue lifetime/stale delivery behavior.

Captured frames remain immutable sealed allocations charged to the shared page budget. All viewers share the same native data and nine-byte Direct flag/timestamp prefix. Cadence follows absolute deadlines, effective FPS and bounded catch-up, and yields at frame boundaries. The first deadline uses saved/effective FPS. Warmup/read-slot acquisition, status files and native queue waits run outside the Tokio event loop. Native read timeout closes subscribers when the owner stops; Runtime shutdown stops the source, native owner and HDMI, joins off the event loop and waits for session cleanup.

Maximum 1440x2560 portrait with Auto/QHD remains unavailable for H.264 and available for H.265; smaller stream presets are accepted. Live API bitrate 101..499 is clamped to the retained C++ minimum500 before crossing the strict native protocol. No new dependency or production native ABI/protocol change is introduced.

`video-source-go-oracle.json` records the complete immutable baseline sources, their hashes and Go toolchain. All 18 original source tests execute with local screen/native/FPS fixture values and no native effects. Rust compares 126 queue transitions, 70 portrait classifications, 16 cadence values, seven keyframe decisions and the exact conflict string: 220 differential values. The development oracle is excluded from the packaged runtime.

Fourteen Rust source fixtures also execute the actual private C worker with synthetic frames: shared H.265/IDR/prefix/ownership, immutable membership snapshots, closed queue memory/wakeup, codec draining and latest passive selection, cancelled replacements, codec retirement/no stale-session frames, errors, live bitrate/FPS, feedback coalescing, timeout/closed owner, portrait admission, saved confined selection/64-subscriber limit, runtime cleanup and responsiveness during warmup/held reads. An actual bounded owner transaction plus eight queued Signal calls verifies the failed-IDR admission fix. Existing native/backend/screen/HDMI regressions remain covered.
