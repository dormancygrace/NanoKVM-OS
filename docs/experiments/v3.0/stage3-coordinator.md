# Manual control and addon arbitration

The isolated Rust socket now reserves manual input through the persisted control-mode manager and cancellable addon lane. Full MCP/PicoClaw/RustDesk services are still pending. /api/ws remains partial because capture/H.264-mode snapshots and media lifecycle are not wired. No production or shared-stand changes.

Preserve /etc/kvm/ai-control.mode (missing defaults to picoclaw), external-file reload, mode activity leases, preempt-before-drain, a 30-second exclusive drain, conditional/idempotent transitions, atomic 0600 persistence and cleanup-failure rollback to off. New operations cannot enter a transition; a release of an already-held or pending held report remains admissible so the activity lease can drain.

Manual input cancels an active HID addon operation and waits at most two seconds for its cleanup/drop without changing the AI mode. Read-only operations are not preempted. Held keys/buttons retain the mode/manual lease; idle completion starts a two-second cooldown when a keyboard/button/wheel/pan event occurred. Pure pointer movement does not create a cooldown. Pending report effects aggregate; switching pointer kinds resets the released pointer state. A PicoClaw session lock (30-minute expiry, renew, force takeover, exact-owner cleanup) filters new manual input in picoclaw mode while allowing releases.

Per-client generation validation, HID writes and revocation serialize under the write lane and the existing ownership transition. Mode leases survive until HID cleanup finishes. Cancelled queued reports cannot clear actual held keys, old reservations cannot reenter after takeover while waiting for addon cleanup, and an unowned viewer closing cannot release another owner's reports. Reservation Drop performs no device IO or write-lane wait on Tokio. Report admission has a separate two-job bound, so waiting for addons does not consume HID or HTTP workers. Failed neutral cleanup persists across descriptor reopen/takeover; a subsequent report must first retry a neutral report. This fixes the original validation/write race and queued-state defects instead of copying them into Rust.
