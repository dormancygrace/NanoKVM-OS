# MaixCDK board-service update — 2026-10-04

Source-only update for the future v2.1-b1. No device installation or restart.

## Source and scope

Update `b29c951647df74e4efa55fd4454efb37e4554be0` to
`30f4b8b7e3f66ded9cfa64fb081b46e30bc27248` (184 upstream commits).
The platform lock verifies the consumed Git objects; only the basic/peripheral
trees changed. YAML headers, NTP client, inifile2 and license objects are unchanged.

NanoKVM links only its existing basic/peripheral subset into `kvm_system`.
Its capture libraries do not use MaixCDK; this update does not introduce the
upstream camera, neural-network, WebRTC or display stacks, or promise more FPS.

The I2C implementation moved from `port/maixcam` to `port/linux_common`.
Compared with the previously pinned unpatched file, its only code additions
are `<algorithm>` and sorting the discovered bus IDs. The production builder
and I2C probe now use the new path. Our I2C patch retains null-directory handling,
fd-zero closure, argument validation and allocation only after successful
address selection, including cleanup on short reads.

Remove `0002-system-file-lifetime.patch`: all its file-close and empty-runtime
fixes already exist upstream. They were already backported in NanoKVM, so they
are preserved behavior, not newly introduced user-facing fixes. New upstream
clock helpers expose zero-valued `cpu0`/`npu0` entries when unavailable; the
existing regression expectations now reflect that behavior.

  16.2.0 toolchain, T-Head C906 instruction profile and `-O2`.
- Link succeeds with `-z defs`, no OpenCV dependency; production manifest
