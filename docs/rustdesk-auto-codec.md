# RustDesk shared codec selection

Version 0.4.1-r0 (protocol basis remains 1.5.0) and normal app 2.0_beta8-r19 replace the independent add-on codec preference. Each authenticated login asks the private media bridge for automatic metadata. SubscribeCurrentVideo resolves the saved device selection, otherwise the live session, otherwise the H.265 default under the source mutex. After an old native read drains it resolves again before subscribing; idle/draining sessions cannot pin a stale codec. The resolved configuration is validated before starting capture, including portrait limits.

The bridge emits the actual subscription codec in OKVF. The add-on verifies the client decoding capability, announces that codec and pins the encoded subscription to it. Changing the device codec retires existing subscriptions and requires reconnect; an unsupported client gets a clear error and cannot switch the common encoder. Direct/relay/WebRTC transport selection remains separate.

Old h264/h265 config values remain accepted for backwards compatibility but are ignored and normalized to auto by the management API. The separate codec dropdown is removed. Package dependency nanokvm-rustdesk-auto-codec=1 prevents installation against an older bridge. Source and recipes are published externally at https://github.com/dormancygrace/NanoKVM-OS-packages/releases/tag/nanokvm-rustdesk-0.4.1-r0; source SHA256 1f5a4502e2d5062fc8f0db3cc141772108a74c3fc5c2e2624d3975ae55515310. No source archive is installed on the device.
