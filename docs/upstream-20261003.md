## Flow offload integration

`CONFIG_NF_FLOW_TABLE=m`, `CONFIG_NF_FLOW_TABLE_INET=m`, and
`CONFIG_NFT_FLOW_OFFLOAD=m` produce three additional modules. AES copy-only CD7
sources were retained and rebuilt for the new kernel ABI (never reuse a 7.2.6 ko).

`S35flowoffload` is packaged in nanokvm-base and the application init tree. The
existing OpenRC nanokvm-policy service applies it at boot; base post-upgrade
attempts it on a compatible running kernel, otherwise boot applies it later.
The transaction replaces only `inet nkos_flow`, leaving `inet nkos_mss` and
foreign policy tables intact. The stock nftables service is not started.

Native wildcard device hooks (`devices = { "*" }`) follow interface creation
and renaming without polling. Established IPv4/IPv6 TCP/UDP forwarding is
eligible after normal priority-0 forward filtering. No hardware-offload flag is
used. Forwarding sysctls and local input/output traffic remain unchanged.

Operational limit: cached flows bypass subsequent netfilter hooks. Per-packet
forwarding filters/accounting, later-priority forward chains, or policy changes
on live connections need coordination with flow offload. Restart this helper
to discard its cached flows after changing such policy. This does not accelerate
WebRTC traffic terminating on NanoKVM itself.

**No runtime flow tests or flow benchmarks were run, as explicitly requested.**
Build/static checks and installation verification are recorded separately.
