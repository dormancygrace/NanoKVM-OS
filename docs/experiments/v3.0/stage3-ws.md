# Live input socket milestone

The isolated Rust runtime now accepts authenticated `/api/ws` upgrades and writes existing keyboard/relative/absolute reports to confined, nonblocking HID descriptors. This is a **partial** WS migration, not complete Go replacement or hardware qualification. The stand remains unchanged and production activation is blocked.

## Implemented and verified
- Session/factory-password gates precede upgrade errors; explicit invalid Authorization does not fall back to the cookie. Origin checks preserve absent-origin clients, scheme/default-port/IPv6 comparison, configured allowlist and trusted-proxy-only forwarded addresses. Comma-separated or repeated forwarded headers do not override the direct address.
- Random socket-specific control leases, viewer opt-out, transfer and sole-viewer promotion reuse the ownership core. Input-owner HTTP routes require the current lease. Cleanup completes before the next grant; generation tickets discard old queued events and all queued tickets after a failed write.
- Separate bounded 200-report keyboard/mouse queues per socket, a 64-socket admission bound and two admitted blocking HID jobs. Each worker revalidates the account/version/expiry at execution. Report IO and ownership cleanup run off the single Tokio event loop. HID retry deadline is 50 ms, legacy relative/absolute framing and Windows pen/auxiliary packets are preserved, short writes fail, and descriptor failure clears the cached handle for reopening. Absolute button release retains the last position.
- Four-KiB message/frame bounds, 90-second read heartbeat, ten-second writes, two-second queue backpressure and revocation close deadlines. Active sessions are immediately canceled after effective rename/role/enabled/password/delete/logout changes; unchanged updates preserve them. Periodic validation detects external store changes, and expiry has its own timer. Session revocation or server shutdown emits 4401 and releases held reports; disconnect/transfer release also runs.
- Runtime shutdown stops socket/HID admission and releases descriptors. Actual nonblocking FIFO backpressure proves the event loop can process a takeover while an old writer stalls, and the old queued keys are discarded when the pipe becomes writable.

## Evidence
`scripts/check-v3.py --host --target --tls` passes 33 tests (12 unit, 15 API contracts, six real-socket integration tests), fmt/clippy with warnings denied, static riscv64 musl release build and QEMU execution. Oversized messages close with 1009 and release held input. Real target HTTPS certificate verification, HTTP 307 redirect/Secure cookie, SIGTERM exit and occupied-port rejection pass. `stage3-ws-qualification.json` records log hashes and binary identity. No latency/CPU/RSS performance claim follows from these fixtures.

New direct dependencies were already resolved transitively: libc 0.2.190, futures-util 0.3.34; tokio-tungstenite 0.29.0 also identifies capacity errors for correct 1009 closes, and supplies an independent test client. Upstream API evidence records unarchived/enabled repositories and last pushes 2026-10-02, 2026-10-01 and 2026-07-11 respectively. Avoid futures-util's unused default macro feature. Cache the Windows descriptor profile on open rather than rereading sysfs for every report. A main-scope cleanup guard also releases input on early/error exits.

## Required remaining work

Capture/H.264-mode snapshots, manual/MCP/PicoClaw arbitration, jiggler and external RustDesk integration remain pending. USB composition/mode/reset/recover must release and reopen descriptors with the existing lifecycle rules. Paste is still HTTP 501 after the newly active lease gate. The ledger labels `/api/ws` partial rather than counting the input-only socket as complete. Media/native ABI, addons/updaters/APK/OpenRC and the agreed hardware window remain subsequent stages. H.265 WebRTC must remain disabled.
