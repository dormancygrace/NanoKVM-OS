# Whole USB composition and monitor association

GET/POST/PUT /api/vm/device/virtual preserve the existing state, response fields, legacy toggles, required seven bool pointers, JSON case/wire-order/null behavior, exact form names, -4 budget errors and -5 stale-revision error. Endpoint limits remain six IN/seven OUT. Drafts and no-ops do not mutate files or execute commands; omitted pointerProfile retains the current profile. Audio enable switches HID-only to normal. RustDesk's shared ensure_remote_access path preserves extra functions and verifies live state even when idempotent, but RustDesk startup is not wired yet.

One admitted manual-priority transaction pauses browser/addon writes, releases held reports, invalidates queued generations and retains the browser lease. Fixed USB stop/start actions have 20-second process-group bounds. The transaction snapshots ten markers and the actual init-script target behind Alpine's absolute compatibility link. Existing marker data/modes survive unchanged, including mounted ISO paths. Install/stop/start/verify failures restore previous contents, modes and presence, rebind and verify the old gadget; secondary rollback errors retain their cause. Multiple boot files are not power-loss atomic. Enabling serial permanently retires only the legacy ttyGS0 getty lines and reloads init, with original inittab mode and other bytes preserved; this migration is deliberately excluded from rollback.

Windows-pointer support uses the real board/chip/container-descriptor conditions. The saved landscape/portrait/QHD profile is associated with a persistent UUID in network byte order. EDID transformation preserves preferred/fallback timings and name/range descriptors, replaces an existing Microsoft association, relocates dense CTA timings without dropping them, and recomputes checksums. The association returns to the old profile when a transaction fails. A later HID descriptor-open failure on an already committed gadget retains its matching EDID; the original operation and reopen errors are both preserved.

Native audio stop and monitor programming are explicit backend calls. Their default backend remains unavailable until the C ABI stage, so hardware success is never fabricated. Isolated tests inject these calls and a fixed command executor; no firmware script, init signal, reboot or stand operation ran. Production activation remains refused.
