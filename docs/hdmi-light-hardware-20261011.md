# HDMI-light: измерение на NanoKVM, 11 октября 2026

Light работает на устройстве и немного снижает расход ОЗУ. Заметного снижения CPU в этом тесте не обнаружено.

Устройство 192.168.4.128, NanoKVM OS Image v1.1-a1 / apps v2.6-a1, Linux 7.2.9-nanokvm-os-r1. Один видимый Linux CPU, фиксированная частота 1,1 ГГц. Тестировали комплект из коммита `920ae6726b718ba93eb9e326f1ac2bade56216c7`. Полная установленная версия всех 19 библиотек после одинакового `strip --strip-unneeded` побайтно совпадает с full-базой эксперимента.

Одна сессия Chrome Main: WebRTC, H.265, 2560×1440, задано 60 FPS и 12 Мбит/с. HDMI-источник — неподвижный рабочий стол Windows. Настройки, серверный исполняемый файл, аппаратное шифрование, GOMAXPROCS и частота CPU одинаковы.

Последовательность full → light → full. Каждый измеряемый запуск — новый процесс с прогревом около 40–45 секунд. По 13 отсчётов с паузой 5 секунд; с чтением procfs каждый прогон занял около 70 секунд. PSS/RSS взяты из smaps_rollup; CPU — разности utime+stime / суммарные тики CPU между отсчётами. Общая загрузка Linux исключает idle+iowait и включает одинаковый сборщик измерений. FPS рассчитан по приращению счётчика аппаратного энкодера и uptime.

PSS всего сервера: 41,58 → 40,95 → 41,58 МиБ. Наблюдаемая экономия составляет около **0,63 МиБ, или 1,5%**. Мгновенные диапазоны PSS пересекаются из-за аллокаций и GC; это короткий эксперимент с одним light-прогоном, а не точная гарантия для любой нагрузки.

В smaps непосредственно у медиабиблиотек и примыкающих анонимных BSS-областей: **1708–1712 → 1036 КиБ**, то есть **−672…676 КиБ**. Из этого **124 КиБ** приходится на Private Dirty, остальное преимущественно на чистые файловые страницы, которые ОС уже может вытеснять. Поэтому эти цифры нельзя целиком трактовать как гарантированный прирост свободной, невытесняемой памяти системы.

CPU light 39,51% находится между двумя full-прогонами 39,14% и 40,73%. Разброс между обычными запусками больше наблюдаемого отличия light от их среднего. Ускорение или снижение нагрузки на CPU не доказано. Частота оставалась 1,1 ГГц; температура около 54–55 °C; swap не использовался. FPS практически одинаков.

Основные видеопулы имеют прежние размеры: 2×7 372 800 и 2×5 529 600 байт. CmaFree составил 12812 / 11984 / 11812 КиБ, MemAvailable в среднем 127580 / 127828 / 127738 КиБ. Эти системные значения не дают чистой оценки эффекта light: они зависят от остального ядра, кэшей и состояния после перезапуска. Утверждать, что light освобождает крупные видеобуферы, оснований нет. В хвостах журналов встречаются предупреждения VPSS; этот тест подтверждает работу потока и сравнивает ресурсы, но не заменяет длительную проверку стабильности.

Ранее измеренное сокращение файлов медиакомплекта **2 059 328 → 1 225 104 байта (−40,5%)** сохраняет смысл для образа и хранения. Для ОЗУ эффект существенно меньше, для CPU выигрыша здесь нет. Малое ядро в эксперименте не задействовалось.

В light-процессе подтверждены только шесть медиабиблиотек из временного каталога, без старых MPI DSO. Первоначальная попытка загрузить их с /data не состоялась из-за noexec; обычный комплект был возвращён, затем кандидат перенесён на раздел приложения. Параметры монтирования не менялись. Неудачная попытка не включена в измерения.

После проверки восстановлен обычный full-комплект. Хеши всех 19 исходных библиотек, скрипта запуска и трёх проверенных конфигурационных файлов совпадают с копией на хосте. В процессе снова загружены 19 full-библиотек; видео работает. Тестовая вкладка закрыта, временный комплект удалён. Исходно включённый USB gadget оставлен в исходном состоянии. Резервных копий на устройстве не создавали. Владение стендом освобождено.

Исходные доказательства сохранены на хосте задачи проверки в `work/device-light-test-20261011/`: `results.json`, `full-a.samples`, `light-b.samples`, `full-c.samples`, соответствующие `.snapshot` и `restoration.json`. Публичный отчёт не включает конфигурационные файлы и реквизиты доступа.

При интеграции повторно пройдены три host-теста границы линковки, проверены SHA256 готовых `libkvm_mmf.so` и `libkvm.so`, а средние PSS и FPS пересчитаны из 13 отсчётов каждого прогона. Аппаратный тест повторно не запускался. После этого теста по указанию пользователя штатная сборка APK и образа переключена на HDMI-light. Это решение не расширяет объём выполненной аппаратной проверки; на стенде после эксперимента был восстановлен full.
