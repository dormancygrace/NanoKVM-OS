# Direct video, encoder state and shared capture telemetry

This stage completes four routes in isolation: GET/POST `/api/stream/state`, GET `/api/stream/video/direct` and GET `/api/stream/h264/direct`. The ledger becomes 68 implemented in isolation, one partial and 135 pending out of 204. `/api/ws` gains capture-status events but remains partial. Full Go replacement, hardware encoding/browser media and production activation remain incomplete.

Direct uses the qualified native Source, one immutable codec/session and one source subscription shared by the transport group. Each viewer has at most eight queued frames and 2 MiB of queued packet data, optional flow window 1..8 and signed `int64` ACK timestamps. The nine-byte keyframe flag/timestamp prefix and sealed native allocation are shared without per-viewer copies. Initial/overflow/resync decoders wait for IDR. Every newly joined decoder requests a coalesced keyframe, fixing the old group’s smart-GOP wait for new viewers. Last-viewer close waits for a bounded in-flight capture; selection retires old queues and replacement waits for source drain rather than cancelling and poisoning the native owner.

Default configurable Direct is H.265; legacy H.264 ignores codec/rate-control query parameters. Valid query pairs survive malformed unrelated fields, first duplicates and empty values match Go, and rate control accepts only `cbr`. Go byte and Unicode quoting is reproduced, including invalid UTF-8. Unicode C1/NBSP escaping was corrected during differential testing. Invalid query errors are rendered literally: this deliberately fixes the old `c.String(err.Error())` percent-format interpretation.

Media registrations use a separate namespace from input-Hub IDs. Streaming does not acquire or release HID ownership. Cookie/Bearer authentication, factory-password and origin gates precede upgrade; account revocation and absolute fractional expiry run independently of the four HTTP execution jobs, including during validation and writes. Direct limits incoming messages to 64 bytes, reads to 30 seconds, writes to two seconds and ping cadence to 15 seconds; write buffers are bounded. Encoder reconfiguration closes with policy1008, oversized input1009 and revoked/expired sessions4401. A single coalesced, joined HDMI publisher replaces unbounded detached viewer-update jobs; revisions reject stale membership updates. Native failure and runtime shutdown close queues and release page-budget ownership.

Encoder state is an atomic active/selected/codec snapshot with `Cache-Control: no-store`. Admin selection accepts the existing Go JSON struct rules regardless of Content-Type, including case folding, duplicate/null/type behavior and first JSON value. It saves the confined selection atomically as mode0600 before changing the live source. Failed persistence preserves selection and active capture; a final legacy symlink is replaced without changing its target. Default Unavailable backend reports an honest inactive selection and policy-close rather than fake capture success.

Capture-status snapshots are bounded to three sorted modes. Public-equivalent successes and repeated failures retain the old timestamp and do not broadcast. Existing and newly joined input sockets receive the legacy JSON-string `capture-status` events. A shared lazy three-second FPS counter counts Source captures once, publishes only into the isolated firmware root, preserves an existing file mode and joins owned publication on shutdown. MJPEG will connect to the same counter and status store in the next stage.

Development references execute complete immutable Go sources with isolated native/account/time boundary fixtures: 564 encoder/query/flow cases, 135 queue steps, 26 state handler cases and 14 status snapshots. Rust also compares the Go SHA256 over all1,112,064 valid Unicode scalar quotes. Original Go tests and source/toolchain hashes are recorded in the three oracle JSON files and their reproducible drivers. Runtime Unicode printable data is a static set of741 Go ranges, covered by `server-rust/native/licenses/go-stdlib.txt` (BSD-3-Clause); it invokes no Go code. Cargo dependencies remain the previously qualified173 SPDX packages.

Twenty-one new tests comprise nine contract/status/FPS/namespace/queue tests and twelve actual synthetic C/native/API/WebSocket fixtures. They cover shared H.265 and FPS/no HID admission, legacy/config conflicts and reconfiguration, signed ACK/resync, role/auth/factory/origin/literal-error gates, expiry/revocation under busy HTTP jobs, sorted existing/new capture events, all26 Go state cases through the Router, save failure/symlink mode, message limit and runtime cleanup, held native last-close/replacement, bounded publisher and default native unavailability. C fixture bytes prove transport, ownership and lifecycle; they do not prove vendor encoding quality or browser decoding. Some input-socket fixtures intentionally have no HID nodes and produce the existing isolated unavailable-descriptor diagnostic.

`stage3-direct-qualification.json` freezes all source, test, native, license and oracle hashes and records261 passing tests on host and generic static riscv64 musl/QEMU (140 unit +121 integration), fmt/clippy, feature-free release and actual host/target certificate-verified HTTPS,307 redirect, Secure cookie, SIGTERM, occupied-port rejection and internal-loopback gates. No native ABI/protocol change, vendor/helper/device/host settings action, package installation, push or publication occurred.
